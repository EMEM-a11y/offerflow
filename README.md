# OfferFlow 求职助手

共享题库与公开岗位发现，配合每个账号独立的求职工作区。公开测试版：https://emcalling.com/。

使用说明见下文；按日期汇总的功能变更见 [迭代记录](CHANGELOG.md)。

## 启动与检查

使用 Node.js 22.12+、pnpm 10.13.1。

```bash
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm check:duplicates
pnpm build
pnpm check:release
```

本地地址固定为 http://127.0.0.1:5174/。不要随意改变网址：浏览器存储按来源隔离。

## 公共与私人边界

- 公开：已收录的共享试题及配图、岗位信息、投递规则、数据来源。
- 本地与公开版共用同一套职测场、岗位雷达和公共数据源，不另设删减版；个人导入题目、练习记录、收藏和诊断仍属于私人数据。
- 私人：基础资料、简历、项目、投递与笔面记录、公司诊断、个人收藏、个人导入题目、错题与练习记录。
- 访客可浏览岗位、练习共享题目；访客操作仅在当前页面内存保留，不自动继承到之后登录的账号。
- 登录后从 Supabase 按用户 ID 加载资料；失败时不解锁、不把本机旧资料上传给新账号。
- 改动使用按账号区分的会话恢复草稿；云端保存用更新时间作条件，发现其他设备的新版本时停止覆盖。
- 新附件存于按账号区分的 IndexedDB；不自动上传云端。退出登录清空页面私人状态。
- 浏览器本地文件不是加密保险箱。共用电脑请使用独立浏览器资料或系统账号。
- 数据库管理员仍有后台管理能力，不是端到端加密。

旧版本未标记归属的 localStorage 和附件库不再自动读取，也没有删除。迁移前需本人核对并备份，不能让任意新登录账号领取旧资料。

## 功能边界

- 求职概览：阶段分布、近期事项、今日摘句和电子木鱼。
- 职测场：共享题库、专项和套卷；登录后保存错题、成绩及个人导入题目。没有启用规则生成题。
- 岗位雷达：默认按公司聚合具体岗位，可按产品/项目、运营/增长、数据/分析等方向筛选；私人岗位诊断仅手动粘贴结论，不调用模型。
- 简历智填：资料复用、字段映射与复制，不承诺自动向所有招聘网站填表或提交。
- 笔面手记：准备、笔试/面试记录、复盘与本地录音。
- 投递记录：投递阶段、环节状态、日期提醒、归档、CSV 导出。
- 数据备份：账号面板导出结构化 JSON；简历文件与录音需要分别下载。导入结构化备份不恢复文件。

## 工作区使用说明

### 岗位雷达

- 先按岗位方向、行业等条件筛选，再选择公司查看符合条件的具体岗位。
- 公司详情顶部的官方招聘入口用于打开公司招聘主页；下方具体岗位的链接用于打开对应岗位页面。没有可确认的公司入口时不冒充官网，异常链接会被拦截。
- “检查新增”用于读取已发布的数据更新，不等于立即运行抓取。“管理员抓取”的权限和操作见下方“岗位更新”。

### 投递记录

- 公司和岗位分列；点击名称编辑投递信息。当前阶段、环节状态、提醒日期可在主表直接修改，修改后自动保存。
- 查询状态链接直接显示在主表；没有链接时通过“补充链接”填写。“下一步”、投递日期、备注等次要信息在详情或编辑窗口中维护。
- 当前阶段保留简历筛选、测评、AI 面试、笔试、一面、二面、三面、加面 / 终面、HR 谈薪、岗位意向书、Offer。AI 面试在分类和统计中归入“测评 / 笔试”，但保留独立记录。
- 笔面环节可标记“待进行”“已完成，待结果”“已通过”等状态，并与关联笔面记录同步。完成笔试或测评不等于已经通过。
- 未通过只分四类：简历未通过、测评 / 笔试未通过、面试未通过、终面 / 最终未通过；主动放弃只有一个选项，不细分轮次。
- 顶部“当前分布”按所选归档范围统计；点击可筛选对应进度。搜索和紧凑的“筛选”入口用于进一步定位记录。
- 归档不是删除：“未归档”隐藏归档记录，“已归档”只显示归档记录，“全部”包含两者。从岗位雷达进入投递记录时可能处于“全部”范围；归档后仍可见时先检查这一选择。归档记录可以恢复。

### 提醒与备份

- 求职概览中的近期事项可标记完成，也可撤销；完成提醒不会自动改写投递阶段或笔面结果。
- 投递记录和笔面记录各自支持 CSV 导出；账号面板可导出结构化 JSON 备份。重要更新后建议保留一份本机备份，简历附件和录音另外下载。
- GitHub 提交历史保存网站代码版本，不是个人求职数据备份；恢复代码版本不会自动恢复个人记录。

## 岗位更新

`node scripts/update-official-jobs.mjs` 通过固定版本的 `job-pro` 只读招聘官网，生成 `public/data/official-live-jobs.json`。当前检查 46 家企业入口；可单独识别校招的直接读取，混合招聘源只保留含明确校招证据的记录。每条记录必须包含岗位名、地点和投递链接，链接还需通过公司域名、共享招聘系统租户以及岗位 ID 一致性检查。单个公司失败时保留该来源上次成功数据；成功来源过少或总量骤降时停止覆盖。

`pnpm update:jobs` 读取公开来源，验证结构、数量及公司链接，原子替换 `public/data/radar-updates.json`。
空数据、格式改变或数量骤减超过 30% 会中止，不覆盖原快照。脚本不调用模型，不读取私人工作区。

GitHub 官网岗位任务每天 22:17 和 07:17 UTC（北京时间 06:17 和 15:17）检查两次；GitHub 定时任务可能延迟。岗位页的“管理员抓取”会先说明权限边界，再由拥有仓库写权限的维护者进入任务页面确认 `Run workflow`；普通用户无需操作，运行完成后可回到岗位页“检查新增”。原有发布流程每天 01:23 UTC 补充检查聚合源。只有仓库上线且 Pages 配置完成后才会生效；更新失败保留已部署版本，并在 Actions 显示失败。
内置校园招聘历史快照不会自动变新；投递规则仍是人工整理，需单独维护。
域名校验只确认链接归属，不代表岗位仍开放、资格符合或规则仍有效。

## 部署

按 [上线检查清单](docs/RELEASE_CHECKLIST.md) 完成 GitHub Pages、Supabase、账号隔离及发布验收。第三方来源尚未明确的使用条件单独记录，不标记为已获授权。
当前仓库已开启 `RELEASE_READY` 进行公开测试发布；新部署仍须先审查公开范围及账号隔离，不能仅因为构建成功就打开。
正式网址为 `https://emcalling.com/`，由 GitHub Pages 托管；发布流程固定使用根路径 `/`，不再使用 `/offerflow/`。域名绑定和 HTTPS 已验收，正式登录返回地址已配置；邮件点击后的完整登录流程仍须实际验收。
登录框在勾选隐私说明后加载 Cloudflare Turnstile。仓库变量 `VITE_TURNSTILE_SITE_KEY` 只放公开 Site key；Secret key 仅填入 Supabase 后台，不进入代码。必须同时启用 Supabase 服务端 CAPTCHA，前端验证本身不能阻止绕过页面直接请求发信。
发信仍使用 `auth.emcalling.com`，不因网站更换网址而重新创建邮箱服务。新网址不自动获得旧网址的本地简历文件、录音和浏览器登录状态；保留原浏览器数据，完成附件导出与新站点恢复后再清理。
只提交本项目，不能把上级“助手团”或本机备份目录一起上传。
